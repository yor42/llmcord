# Running a server

## Conversation participants

Human messages sent to the model include the speaker's Discord display name and stable user ID. Names are saved with each message, so two members sharing a nickname remain distinct and a renamed member keeps the same identity. Mentioned users are identified separately from the person speaking. This is ordinary conversation attribution; world/channel guidelines still supply the roleplay setting.

Recent human chat observed before a bot turn is kept with that branch and included in later replies and summaries, within the configured context and retention limits. Rewinding to an earlier reply excludes later participants and messages. Identity guidance also applies to custom prompt presets; `{{user}}` means the current speaker.

Older saved messages from before this feature retain their user IDs; historical display names that were never recorded cannot be recovered. Speaker names and mention metadata expire with conversation history. Personal facts remain scoped to the consenting user ID and character.

## Worlds, hubs and casts

| Scope | What it controls |
| --- | --- |
| World | Home for characters and world lore. A world channel can use only characters from that world. |
| Hub | The lobby: a crossover setting. Administrators choose its allowed worlds; a hub guest keeps its own home-world lore and receives hub lore. Each hub has a tone, **In character** (default) or **Off duty**: off duty characters keep their personality but chat casually and do not push their world's plot. World channels are always in character. |
| Bound channel | Chooses one world or hub and adds channel lore, a default cast, an active cast, and an ambient setting. Multiple channels can share one world or hub. |
| Thread | Inherits its parent channel's world or hub, channel lore, and ambient setting. It has its own cast and conversation history. |

A default cast is an administrator's starting selection for a channel. Members can change the active cast without editing that default. Setting a new default also resets the channel's active cast to it. A thread uses the parent channel's active cast until someone sets a thread cast. A cast can contain up to the server's **largest cast** (an admin sets it in the dashboard under Server settings; default 5, at most 15) eligible characters; the director selects at most three to speak in one turn.

`/summon` invites an eligible character for one turn. In a hub, this allows a linked-world guest outside the current cast to join an explicit skit. Summoning does not change the cast. A hub character outside the active cast will not join ambiently, unless it is a favorite of the member who posted and that member uses the step in mode (see Favorites).

## Starting and continuing scenes

- Mention the bot in a bound channel, reply to a saved character webhook message, or run `/summon` with a prompt. These are explicit invitations.
- Replying to an older character message follows that message's saved parent chain. Later messages on the other branch are excluded. The bot does not need Discord's visually nested replies for its character lines; it stores the parent message IDs internally.
- A new invitation may include up to 12 recent human messages from the previous 10 minutes. A current-branch reply can also use intervening group messages. `/scene reset` prevents the next invitation from using earlier nearby context.
- The director chooses one or more speakers from the active cast. Each chosen character receives a separate sequential model call, so later speakers can react to lines already posted in the turn.
- Character lines use webhooks with the character name and PNG avatar when present. If the bot cannot manage webhooks or a channel has reached its webhook limit, it reports the failure in the channel.

Ambient mode is off until an administrator enables it in a channel. It waits for two new human messages and a 120-second channel cooldown by default. Then a simple rule (English and Korean, no model call) decides whether a character joins in. It counts as an invitation when a message names a character in the cast ("Luna, …", "루나야"), asks the room ("what do you think?", "anyone?", "어떻게 생각해?", "너는?"), or reacts with a question or a laugh right after a character spoke. A member whose favorite is available is also answered when they ask a question. Plain chat stays silent and costs nothing; when the rule invites, at least one character answers. Check explicit turns before enabling ambient mode.

Text attachments are read up to the configured size and added to the turn. Image attachments are bounded by count and size and need an image-capable dialogue model. Other attachment types are rejected. Long character lines are split into Discord-safe message chunks.

If you upgraded from a version where admin commands were top-level (for example `/lore add`), re-check any per-command overrides under Server Settings → Integrations: they do not carry over to the new `/admin …` commands.

Character and space options (`character`, `characters`, `space`, `hub`, `world`) suggest matching names as you type. Discord presents the parameters for each slash command. Most command responses are ephemeral, including context and memory listings. Character skit lines appear in the channel.

## Items and the shop

Members spend the server currency (see `/balance` and `/daily`) on **items**: small toys with a random result and no effect on scenes or balances. A server starts with five: **Magic 8-ball**, **Fortune cookie**, **Dice** (six sides), **d20** and **Tarot**. Admins turn each item on in the dashboard's **Shop** tab; nothing is for sale until they do.

- **Buy.** `/shop` lists what is for sale, with your balance and what you already hold. The price is taken from your balance as a normal ledger entry (it shows in the Currency tab as a purchase). If an admin changes a price after you opened `/shop`, the purchase is refused and you open `/shop` again.
- **Consumable or reusable.** A **consumable** (fortune cookie, tarot) is used up each time; you can hold up to the server's hold cap (default 10, 1 to 99). A **reusable** item (8-ball, dice, d20) is held once and has a short cooldown between uses, per member (30 seconds for the 8-ball by default; admins can change it).
- **Use.** `/use` or the **Use** button in `/inventory` posts the result in the channel as an embed. The result is picked by the bot, not the model, and is saved in the use log.
- **Admins.** The **Shop** tab sets, per item, whether it is **for sale**, whether **use is allowed** (turn it off to stop a bad line without refunds; members keep what they hold), the price, the cooldown, the number of sides for dice and d20, and **custom lines**: lines added to, or replacing, the built-in ones for the 8-ball and fortune cookie. A price change affects new purchases only. Tarot's deck is fixed. The tab also shows the use log and the hold cap (the most of a consumable one member can hold).
- **Mistakes.** Reversing a purchase in the Currency tab gives the coins back and takes one of that item away if the member still holds it; if it was already used, only the coins return and the ledger note says so.
- **Not included yet.** Trading or gifting, selling back, items that change balances or scenes, and creating new items from the dashboard.

## Blackjack

Blackjack is the first game that uses the server currency (see `/balance` and `/daily`). Admins can turn it off for the whole server in the dashboard's Games tab: `/blackjack` is then refused and open tables close with every bet refunded. Players bet against the bot's dealer. The deck order is fixed before the deal (the round's seed hash is shown on the table). With **Characters talk at the table** on, a model chooses each character seat's moves (below); like any player's choice, a character's hit changes which cards the later seats and the dealer draw. With the switch off, characters play by the house rule and no model is used.

- **Turn it on.** An admin runs `/admin games channel enabled:True` in the channel. Bet limits come from `/admin games bets`. The same settings are in the dashboard's **Games** tab.
- **Play.** `/blackjack bet` opens a table in the channel, or joins the open one. Others join with their own bet for 30 seconds, or anyone seated presses **Deal now**; **Leave** refunds a bet before the deal. When the cards are dealt, each player in turn presses **Hit**, **Stand** or **Double** (only on the first two cards, and only if you can pay the extra stake). Only the player on turn can press; a player who does nothing for 60 seconds is played automatically (hit below 17, else stand), and each automatic or manual move gives the next decision another 60 seconds. After a round, **Play again (same bet)** joins the next round and **Leave table** leaves (during a round it says you can leave when the round ends). The table closes after 2 minutes with nobody joining a new round. When the last player has moved, the dealer's play is shown step by step (the hidden card, then each card about 1.5 seconds apart) before the results; the round is already settled by then. A **How to play** button under every table message gives anyone a short private guide. When a table closes (idle, everyone left, or games turned off), its message shows the closing text and a summary of its last settled rounds (5 by default; admins can set 1 to 20 in the dashboard's Games tab): the dealer's total, each seat's result (`+10`, `−5` or `push`) and, over several rounds, each player's net.
- **Bring your favorites.** `/blackjack bet:10 favorites:True` in a channel bound to a world or hub also seats your eligible favorite characters (not archived ones), each beside you as a character seat marked "(with @you)". Each bets the same amount from its own wallet, or less if its wallet or the largest bet is lower; a character whose wallet is below the smallest bet, one already seated, or one that does not fit (the table holds 7 seats) is skipped, and your private reply says who sat and who did not and why. In a channel that is not bound the reply says characters can't sit there. **Play again** and **Leave** only affect you; **Play again** re-seats you alone, and **Leave** before the deal also takes your characters off the table and refunds their wallets. A character's winnings go to its wallet.
- **Character turns.** A character on turn moves about 2 seconds after the previous move; members cannot press for it. With **Characters talk at the table** on (the default), each decision is one model call (the director model) that sees only the character's name and card text and the visible table, never lore, scene history or memories, and may add a short line posted through the character's webhook (nothing is saved to the scene). The call has a 20-second limit and follows the spending cap; if it fails, is too slow or is over the cap, the character plays by the house rule (hit below 17, else stand) and says nothing. With the switch off, no model call is made. If an admin sets **Character moves** to **Play style only**, the house rule picks every blackjack move and the model only adds the short line. Cost: one small call per character decision, and there is no per-member limit, so a member who keeps bringing favorites to a busy table adds calls; the daily limit and the server's spending cap still apply, and an admin can turn the switch off or lower the **Table talk calls per day** limit (default 100 per server day, approximate when several tables play at once; once it is reached, characters play by the house rule and stay quiet until the next day).
- **Rules.** Six decks reshuffled every round, no splitting. By default the dealer stands on all 17s, a natural blackjack pays 3:2 (rounded down), a push returns the bet, and there is no insurance or surrender. Admins can change these in the dashboard's Games tab (**Blackjack rules**): the dealer stands on 16, 17 or 18 (hitting soft 17 is an option only for 17), blackjack pays 3:2 or 6:5, ties push or go to the dealer, and **Insurance and even money** and **Late surrender** can be turned on. A change applies from the next new round; a round already open keeps the rules it was dealt with. Every table message repeats the round's rules in a gray line above the seed line, and **How to play** describes them.
- **Insurance and even money.** When the dealer shows an ace and insurance is on, each player is asked in turn before anyone plays: **Insure (N)** puts up half your bet (N, bets of 2 or more, and you must be able to pay it), **No insurance** declines, and a player with a blackjack gets **Even money** instead. If the dealer has blackjack, insurance pays 2 to 1 (you get N back plus 2N), so a lost hand about breaks even (an odd bet loses 1); if not, N is lost. Even money pays the bet 1 to 1 whatever the dealer has: the result is fixed at once, and it is paid when the round ends. A player who does nothing for 60 seconds declines, and a character declines unless its model chooses to insure (or, with a blackjack, to take even money). Insurance comes from the same wallet as the bet and is refunded if the round is cancelled.
- **Surrender.** With late surrender on, a player on their first two cards, after the dealer has checked for blackjack (so not when the dealer has it), may press **Surrender** to give up the hand and get half the bet back (rounded down). The result shows "surrendered".
- **Typing your move (Experimental).** If an admin turns on **Read moves from chat** in the Games tab, you can also say your move in the table's channel when it is your turn ("fine, hit me", "stand", "한 장 더", "서렌"). English and Korean work. The bot never plays it by itself: it replies with a **move check**, for example "Did you mean **Hit**?" with **Hit** and **Just table talk**, or "Did you mean **Hit** or **Stand**?" when it is not sure, and only you can press its buttons. If it does not look like a move, the bot says nothing. Your message still reaches the characters as usual. The check belongs to your turn: it disappears when the turn ends, the turn timer keeps running, and the normal table buttons still work. It can miss or misread a move. Turn move checks off for yourself with `/game spoken_moves setting:Off` (and back on with `On`); turning them off also deletes any phrases kept from your messages. If the admins also turn on **Keep phrases for tuning**, a message the bot got wrong (you pressed **Just table talk** or the other move, or it missed a move you then played with a table button) is kept so they can teach the bot this server's phrasing; the dashboard does not show who wrote it, and kept phrases are deleted after the server's history retention period.
- **Money.** The bet leaves your balance when you join and the payout is added when the round ends, each as a ledger entry. If the bot restarts or an admin turns games off in the channel, unfinished rounds are cancelled and every bet is refunded.
- **Check the deck.** Each round shows a short fingerprint of its secret seed ("Seed hash") when the cards are dealt, and the seed itself when the round ends. Run SHA-256 over the revealed seed text and compare the first 12 characters with the hash shown earlier: they match, so the deck was fixed before the first card.

## I Doubt It

A card game for 3 to 8 players, also known as Cheat or BS, and the first game built around table talk. Members and characters play together in a bound channel; in a game channel that isn't bound to a world or hub it is a **humans-only table** (at least 3 members, no characters). Admins can turn it off in the dashboard's Games tab.

- **The game.** All cards are dealt (one deck for 3–5 players, two for 6–8). On your turn you put down 1 to 4 cards face down and **claim** they are the rank that is due: aces first, then 2s, 3s and so on up to kings, then aces again. The claim may be a lie (a bluff). The first player to empty their hand wins.
- **Doubt.** After each play there is a 15-second **doubt window**: any other player can press **Doubt**, and the first press counts. The played cards are shown to everyone. If any is not the claimed rank, the player who claimed takes the whole **pile**; otherwise the doubter takes it. The window also closes when the next player plays (they let the claim stand) or when time runs out. A player who plays their last cards wins only once the window on that play closes without a successful doubt.
- **Typing a doubt (Experimental).** If an admin turns on **Read doubts from chat** in the Games tab, you can also doubt by writing it in the table thread during the doubt window ("liar!", "I doubt it", "bs", "구라", "뻥치네", "거짓말쟁이"). The bot replies "Did you mean **Doubt it!**?" with **Doubt it!** and **Just table talk**, and only you can press them; pressing **Doubt it!** works exactly like the table's **Doubt** button (the first doubt still counts). The check disappears when the window closes, and the window does not wait for it. Messages with a "not" or "안/말/못" in them ("no doubt", "구라 아니야") are left alone. Your message still reaches the characters. Turn checks off for yourself with `/game spoken_moves setting:Off`.
- **Open a table.** `/game start game:doubt` in a game channel posts a lobby and opens a public **table thread** on it. Others press **Join** (or **Leave**). In a bound channel `favorites:True` also seats your favorite characters, marked "(with @you)", and the host can press **Fill seats** to add characters from the channel's cast, marked "(house)". The host presses **Start** once at least 3 players are seated (it stays disabled until the thread is ready). A lobby nobody starts closes after 5 minutes. Nobody joins once the game has started.
- **Play.** The game happens in the thread. A pinned board shows each player's card count, the pile and the rank due; one turn message, edited in place, shows the last claim, who is next and the **Doubt** and **My hand** buttons. If the chat buries it (8 messages), it is posted again at the bottom on the next turn. **My hand** (or `/game hand`) shows your cards privately and, on your turn, a picker: choose how many of each rank to put down. A player who does nothing for the turn time (60 seconds by default, set in the Games tab) plays automatically: one card of the due rank if they have it, otherwise one random card as a bluff. Two automatic plays in a row forfeit the seat; its cards leave the game.
- **Characters.** A character plays on its own about 2 seconds after its turn starts, and only once the doubt window on the previous play has closed. With **Characters talk at the table** on, each of its plays and doubts is one model call that sees only its own hand and the public table (claims, counts, revealed cards), never other hands; at most the two most suspicious characters are asked about each claim, and a character that can see a claim is impossible (it holds too many of that rank) doubts it without a call. Calls count toward **Table talk calls per day**; when the switch is off, the limit is reached or a call fails, the character plays by a fixed policy with its own steady habits (some bluff more, some doubt more).
- **Table talk.** The thread works like any skit thread: with **Characters talk at the table** on, the seated characters (only they) answer members' messages there by the channel's usual rules, and a doubt's reveal, a player down to one card and the end of the game can prompt one of them to comment. Each character knows only the public table and its own hand (players appear to it by display name, never by Discord ID). Talk counts toward the daily table talk limit (failed calls too; one reply can use a few calls, so the limit may be passed slightly) and the spending cap, the game never waits for it, and table talk is not used for memories or summaries. Admins who keep a turn log can read a character's hand there, as with any prompt.
- **Ante and pot.** Off by default. When an admin sets an ante, each player pays it on joining (a character from its own wallet) and gets it back on leaving the lobby or if the table is cancelled; the winner takes the whole pot. Losing a doubt costs no currency.
- **End.** The result is posted in the thread and the lobby shows a one-line result. The thread stays open 10 minutes for banter, then is archived and locked. If the bot restarts, unfinished games are cancelled and antes refunded.
- **Permissions.** The bot needs **Create Public Threads** and **Send Messages in Threads** in game channels. Without them the table closes at once (antes refunded) and the host is told which permission is missing.

## Texas Hold'em

A poker game for 2 to 9 players, played as a **cash table**: no-limit, with hands dealt one after another until the table closes. Members and characters play together in a bound channel; in a game channel that isn't bound to a world or hub it is a humans-only table. Admins can turn it off, and set the blinds, buy-in range, move timer and whether **Assist** may be used, in the dashboard's Games tab.

- **Open a table.** `/game start game:holdem` posts a lobby and opens a public table thread. Press **Sit** and enter your **buy-in** (the lobby shows the allowed range; the default is 100 big blinds). The buy-in comes out of your wallet and becomes your **stack** of chips. In a bound channel `favorites:True` also seats you and your favorite characters, and the host can press **Fill seats** to add characters from the cast ("(house)"). Characters pay from their own wallets, and one that cannot afford the smallest buy-in is skipped. The host presses **Deal** once two players are seated. A lobby nobody deals in closes after 5 minutes.
- **A hand.** Each player gets two private **hole cards**; five community cards follow in stages (flop, turn, river). The two players left of the dealer button post the **blinds**. On your turn press **Fold**, **Check / Call** or **Raise** (a private picker offers the smallest raise, half pot, pot and all-in, or **Exact amount**). **My cards** (or `/game hand`) shows your hole cards privately. A bet you cannot cover goes all-in, and side pots are split out automatically. At showdown the board, the shown hands, each pot and its winner are posted; if everyone else folds nothing is shown (the winner may press **Show**). A seat that does nothing for the move timer (45 seconds by default) checks if that is free, otherwise folds; two timed-out hands in a row cash the seat out. Characters a member brought leave with that member (when they bust, leave or are cashed out for timeouts) and are cashed out to their own wallets.
- **Between hands.** The turn message becomes a 15-second pause with **Sit**, **Leave**, **Rebuy** (top up to the largest buy-in) and **Deal now**, then the next hand deals by itself. A player who runs out of chips leaves the table and may sit again. A character plays on its own: it chooses by model when **Characters talk at the table** is on, **Character moves** is not "Play style only", and the daily limit is not reached; otherwise it follows its saved **Play style** (see the dashboard's Characters), which shapes how loose, aggressive or bluff-prone it plays.
- **Assist.** If the server allows it, the host can turn on **Assist**: **My cards** then also shows your current hand's name and your chance to win against the other players, as a percentage. It is a private aid; characters never see it.
- **Money.** Chips move only inside the table: your wallet changes when you sit, rebuy and cash out (leaving, going bust, or the table closing), never per hand. Closing the table, the idle timeout, an admin turning Hold'em off or a bot restart voids an unfinished hand (everyone keeps their pre-hand stack) and cashes every stack out. The ledger shows "Texas Hold'em buy-in / rebuy / cash-out (table N)".
- **Check the deck.** Each hand shows a short fingerprint of its secret seed. The seeds stay hidden while the table is open (a seed would show the cards of players who folded) and are all posted in the thread when the table closes. Anyone can then replay every hand from them.
- **Table talk.** The thread works like an I Doubt It thread: only seated characters answer, each knowing the public table and its own hole cards, never anyone else's, and showdowns, busts and all-ins can prompt a comment. The same talk limits apply.
- **Permissions.** Like I Doubt It, the bot needs **Create Public Threads** and **Send Messages in Threads** in game channels.

## Language

The bot speaks English and Korean (한국어).

- Replies only you see (errors, `/inventory`, `/shop`, move checks) use your Discord language. Change it in Discord under User Settings → Language.
- Public messages (game tables, game updates, notices) use the server's **Bot language**, set by an admin in the dashboard. By default this is the server's Discord language in a Community server and English elsewhere.
- Command and option names stay in English in every language; their descriptions are translated.
- Characters answer in whatever language the conversation uses; their lines are never translated.

## Admin dashboard

The dashboard is designed for the Pi's Tailscale HTTPS address. A visitor signs in with Discord. Each server page and change checks that their Discord account is an administrator of the selected server; changes are checked again on every action, and uploads and sign-out also require a CSRF token. See [deployment](deployment-raspberry-pi.md) for login setup.

From a server page, an admin can create worlds and hubs, link worlds to hubs, bind channels, choose default casts, toggle ambient mode, turn the reply footer on or off, choose the server timezone, add/edit/pin/promote/delete shared lore, manage characters, and manage named lorebooks. Changes are read from SQLite on the bot's next turn; there is no separate publish step.

For a card, select its home world and upload a V2/V3 `.json` or `.png` file. The preview shows its name, description, personality, scenario, opening line, lore-entry count, and PNG avatar when present. Saving an existing name requires a replacement confirmation. Reimports preview local conflicts and preserve manual additions and avatars unless explicitly replaced. Editing the home world can remove the character from casts where it is no longer eligible. Archived characters are not eligible for scenes, except as archived favorites (see Favorites).

The dashboard edits the main text fields of an imported card. Use the Lore workspace to edit its embedded character entries. For server and channel lorebooks, use the [import workflow](lore-and-memory.md#importing-sillytavern-lorebooks).

The bot's operators (who run the bot itself, not per-server admins) also get a **Bot settings** page with bot-wide spending caps. When the hard cap is reached, characters stop replying until the reset day; `/summon` tells the member privately, and other messages get no reply unless the operator turned on the channel notice. See [Bot settings and spending caps](admin-console.md#bot-settings-and-spending-caps).

See [Admin console](admin-console.md) for the NiceGUI workspace, rule transfers, emotion avatars, and per-server prompt presets.

## Favorites

Each member can keep favorite characters with `/favorites add`. A favorite has an effect only in channels where that character can already appear (its world, or a hub linked to it); it never lets a character into another world. Favorites are a preference, not a personal fact, so they need no `/memory opt_in`.

- **Lean** (default): when you post, favorites that are in the channel's cast are more likely to answer you, and they get a better chance at ambient replies. Other members are still answered.
- **Step in**: a favorite who is eligible here but not in the cast can also answer you, for that message only. The saved cast does not change.

Choose with `/favorites mode`. Admins set the favorites limit and the largest cast in the dashboard (Server setup, Server settings); lowering a limit keeps existing casts and favorites.

**Archived favorites** (off by default): an admin can turn on "Archived favorites can answer their members" in Server settings. Members can then keep archived characters as favorites; they are listed with "(archived)" and count toward the limit. An archived favorite answers only the member who chose it, only to that member's own messages (mentions, replies and ambient), and only in channels where its world is available. It acts like step in in both modes, but never joins a cast, a game or `/summon`, and never answers other members. Turning the setting off hides them again without removing them. While it is off, hidden favorites don't count toward the limit, so after turning it back on a member can be over the limit; their list can then shrink but not grow, as after lowering the limit.
